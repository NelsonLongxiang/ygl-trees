01

架构设计

三段流：人提交模糊材料 → agent 预处理成机器判据 → 确定性检查器跑出可重放的结论。结构化是预处理的输出，不是专家的输入义务。

1.1三段流

人 · 业务专家
材料提交
标题 + 一段话 + 附件（xlsx / png / pdf）。零 SQL、零代码、零字段义务。
agent · 预处理
提取 → 翻译
读附件提值（带出处锚点）；一段话翻译成候选验证单元；专家逐项确认。
agent · 驱动
确定性检查
六型检查器拓扑执行；模型调用全部前压，run 阶段零模型。
交付
真 + 产物
结论可重放 + 证据包 + 可重跑的规范资产 + 人工项 task。
核心立场：判定零概率

模型只出现在预处理（人话 → 判据结构化）与采证编排。verdict ∈ {PASS, FAIL, NEEDS-HUMAN, ERROR}，语义判不了的判据在预处理阶段就标 human——不让模型给概率冒充结论。

1.2VU = 纯函数，规范 = 管线

每条验证单元（VU）是一个纯函数，输入 → { verdict, evidence, outputs }。输出带类型，可被下游引用——一个验证器的结果是另一个验证器的输入。

// 对账三连例：上游 FAIL 的行集正是下游要消费的证据
V1 (sql)      : 拉超期未对账账单             → outputs: { rows: rowset }
V2 (sql-pair) : $V1.rows 逐行 vs 报价基准      → outputs: { violations: rowset }
V3 (count)    : $V2.violations == 0        → verdict FAIL 带样例行

⌁拓扑执行

执行序 = 拓扑序；成环在 prepare 阶段拒绝（复用科技树 DAG 引擎的拓扑排序与环检测）。

⤵级联语义

上游 FAIL → 输出照常产生；上游 ERROR → 下游标 ERROR 只断依赖分支，独立分支照跑。

≡纯数据流

同输入同输出同判定。报告 = 管线执行 trace：每级收到什么、产出什么、判了什么。

1.3检查器闭集 × 比较域

检查器类型判定来源
sql违规行数（SELECT 前缀门 + 分号拒绝）
sql-pair两表按键值比对，容差 ±ε
count计数阈值（telemetry 同语法）
exists存在性
command退出码 / stdout 字面匹配
human人（不做假确定性）
比较域容差形态
数值±绝对值 / ±百分比
字符串精确 / 包含 / 正则
日期时间窗口（±N 天）
布尔—
集合子集 / 交集为空 / 差集点名
计数阈值区间
比例两条 SQL 互比，百分比容差

闭集纪律：新增检查器类型 = 破坏性变更（走 schema 版本）。六型 × 七域之外的判据，预处理一律标 human，不会静默漏判。

02

工程实践

确定性不是一句口号，是七条可检查的工程纪律。

交付契约：真 + 产物

真 = 只有可证伪、可复验的结论才交付：PASS/FAIL 是事实陈述（带证据 + 同版本同输入重放逐字段一致）；NEEDS-HUMAN / ERROR 是诚实的非真态，绝不冒充真假。

产物 = 专家拿走四件：处置清单报告（FAIL 置顶）+ 证据包（锚点全链）+ 规范资产（可重跑 / 可毕业 / 可挂树）+ 人工项 task（零未处置）。

#纪律可检查的形态
1可重放同一数据快照 + 同一 spec 版本重跑，报告逐字段一致；时间戳仅入 meta 不入判定
2报告不可变每 run 一个 artifact（kind=verify-report），永不覆写、永不清洗
3契约先行spec / VU / 报告三 JSON schema 是唯一接口真相；任何语言实现同一契约即可互换
4进程边界语言间只经子进程 + JSON，禁跨语言 FFI 纠缠；每个组件可独立测试、独立发布
5门禁随语言Node = vitest + contract:audit；Python = pytest + ruff（提取黄金样本）；Rust = cargo test + clippy
6提取值带锚点每个从材料提取的值都有出处（文件 · 页/sheet/行/区域），确认视图可见
7模型只在前置所有模型调用在 prepare 一次性完成并冻结进 VU；run 阶段零模型调用

→发现

FAIL 3 项 → 处置清单置顶；NEEDS-HUMAN 1 项 → 自动 task。

⚒处置

业务方修数据（供应商发票更正 / 超期单完成对账）。

↻复核

同 spec 重跑 → run 版本对比（数据漂移轴）；绿了即闭环。稳定 3 轮 → 毕业成 patrol 每日巡检。
