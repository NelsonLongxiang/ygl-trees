# 测量与棘轮（Measurement & Ratchet）

> 本文回答一个问题：**怎么让「不退化」变成机械事实，而不是每次发布前的口头承诺。**
> 直接来源是 claude.ai 两周三倍提速的复盘（2026-09-23）与本仓 0.30/0.84 两次「门禁绿但产品坏」的教训。

## 一、测量是第一步，不是第三步

性能/质量工作的顺序通常被写成「先改，再测」。复盘文章里最高杠杆的动作是把它反过来：

1. **先造测量点**（能重复、能比较、能进 CI）；
2. 再改；
3. 改完让测量点自己说话。

没有测量点的改动，只能靠评审席的记忆来守——而记忆不是门禁。
本仓已有的测量点：`pnpm test` 四段（build / unit / demo / contract）、`pnpm readme:verify`（文档命令逐条真跑）、`node scripts/gate.js`（包结构）、`pnpm bench`（性能七席）。

## 二、棘轮（ratchet）：只降不升

`scripts/ratchet.mjs` + 仓库根 `ratchet-baseline.json`。指标三条：

| 指标 | 来源 | 容差 | 为什么选它 |
|---|---|---|---|
| `bundle_bytes` | `dist/bundle/bin.cjs` 字节数 | 2% | 发布产物的确定性度量；膨胀会直接变成启动与安装成本 |
| `web_dist_bytes` | `dist/apps/web/dist` 合计 | 2% | 前端资源只增不减是默认命运，必须显式认账 |
| `cold_start_ms` | `--version` 冷启动中位数（预热 1 次不计 + 5 次取中位） | 30% | 只抓大滑坡；单次墙钟噪声大，宽容差 + 中位数。预热样本是必须的：干净检出首次触碰 bundle 被杀毒与磁盘冷缓存放大，否则同一 commit 在主树 held、在新 worktree regressed，闸门测的是路径新不新而非启动快不快 |

行为：

- **变好 → 自动收紧基线**（棘轮齿），输出写明旧值 → 新值；
- **变坏超容差 → rc=1**，要么优化，要么 `--write` 显式认账（基线更新进 diff，评审可见）；
- `--json` 给机器读，`pnpm test` 末段自动跑。

**刻意不测的东西**：单测总时长、demo 总时长。并行负载下它们测的是机器忙闲，不是产品快慢——复盘文章的口径是「flaky 或与墙钟不相关的 benchmark 直接 unship」。要测启动成本就用启动探针，不要用整机负载的副产品。

## 三、漂移守卫：结构一旦冻结，就只能按版本动

三处冻结件，各有机械守卫：

| 冻结件 | 守卫 | 变更通道 |
|---|---|---|
| 语料（`packages/verify/core/corpus/`） | `corpus/freeze.mjs` + `manifest.json`（129 文件 digest） | 只增不改；改=升 `corpus_version` 并写 CHANGELOG 差异表 |
| 契约字段（`VerifySpec`/`VerifyReport`） | `tests/shape.spec.ts`（字段路径+类型快照） | 1.0 内文不动；形状变更走 1.0→1.1 |
| 视觉 token（DESIGN.md） | `apps/web/tests/tokens.spec.ts`（13 色逐键 + 零裸 hex） | 改色只能从 DESIGN.md 起 |

三者的共同点：**守卫是「相等比较」，不是「人工复核」**。人审会累、会漏、会看走眼；相等比较不会。

## 四、一次真实的反面教材（本仓）

0.84.0 门禁全绿发布，随后 demo 的 `agent log` 断言在 0.87.1 变红——因为 `claim link` 自动评估新增了事件，把树事件挤出了 200 条窗口。当时的门禁测的是「命令退出码」，没测「事件窗口里的形状」。修复不是加人肉检查，而是把断言改成对**语义**的检查（事件 kind 存在性）。

结论：**门禁要测「你会关心的那个东西」，而不是「最容易测的东西」。** 这就是为什么 ratchet 挑确定性度量、形状守卫生成字段快照，而不是笼统地「跑一遍看看」。

## 五、怎么加新的测量点

1. 找一个**失败模式**（不是找一个数字）；
2. 写一个能在失败时变红的探针；
3. 让探针在本地 `pnpm test` 能跑、CI 能跑、失败信息能指向修法；
4. 若它噪声大（并行/网络/时钟），先修测量方式，再上闸——噪声门禁最终会被 `--force` 绕过，等于没有。
